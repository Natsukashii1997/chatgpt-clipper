# ChatGPT 回答收藏器 PRD v2

> 2026-11-02 定稿为开发基线，替代 GPT 起草的《ChatGPT 高保真可编辑导出器 PRD v1.0》（原文存于 [reference/gpt-prd-v1/](reference/gpt-prd-v1/)，只作参考）。
> 形态：Chrome 桌面版 MV3 插件，常浩自用，也可以打成 zip 包发给别人装（开发者模式加载，2026-11-03 用户决定）；不上架。只做电脑版。

## 1. 为什么做

ChatGPT 聊天模式的好回答常带卡片、分栏、图标、表格等版式。复制粘贴只剩文字，截图又不能搜索和引用，所以好答案存不下来。

**目标**：在 ChatGPT 网页上一键把某条回答原样存进 Obsidian，以后能看到原样、搜得到、能引用。

**v1 改了什么**：v1 把目标定成“高保真可编辑导出器”（编辑器、图层树、E0–E3 编辑分级、Figma、SSIM 评分）。用户的真实需求是收藏，编辑功能放到最后一期（M3），届时再参考 v1。

## 2. 存什么：每条回答一张长图 + 一篇笔记

> 2026-11-02 用户决定只留长图，不要离线 HTML：Obsidian 能直接显示 PNG，HTML 在 Obsidian 里默认不显示；两者的文字都检索不到，检索、引用、知识库调用全靠笔记 `.md`。

| 产物 | 用途 | 要求 |
|---|---|---|
| `answer.png` | 看原样 | 整条回答的长图，和页面所见一致；不含侧栏、输入框、操作按钮 |
| 笔记 `.md` | 搜索、引用、双链 | frontmatter + 提问 + 嵌入长图 + 正文 Markdown |

笔记模板：

```markdown
---
source: chatgpt
url: https://chatgpt.com/c/…
captured: 2026-11-02 16:30   # 北京时间
title: 整体业务逻辑
tags: [chatgpt收藏]
---
> [!question]- 提问
> （提问原文）

![[answer.png]]

（回答正文 Markdown）

```

存放位置（默认，可在设置里改）：

```
<Vault>/00 待整理/ChatGPT收藏/2026-11-02 整体业务逻辑/
  整体业务逻辑.md
  answer.png
```

## 3. 怎么用

1. 打开 ChatGPT 对话，每条回答旁出现「收藏」按钮（或点插件图标进入选择模式）。
2. 点一下 → 显示进度（截图 / 存档 / 转文字 / 写入）→ 完成后提示保存位置，可点开。
3. 首次使用时在设置页选一次 Vault 里的目标文件夹，之后不再询问；浏览器收回授权时再提示一次。

## 4. 功能需求

| 编号 | 需求 | 验收 |
|---|---|---|
| FR-1 | 只收藏用户点选的那一条回答 | 5 条回答的对话里只得到选中那条，不含提问气泡、按钮、其他回答 |
| FR-2 | 长图 | 超过一屏（≥4000px）的回答完整截取，无重复行、无缺口、无悬浮控件；和页面截图目视一致 |
| FR-3 | ~~离线 HTML~~ | 2026-11-02 用户决定不要（见第 2 节），编号保留不复用 |
| FR-4 | Markdown | 可见文字 100% 保留；标题、列表、表格、代码、公式源码、链接结构正确；卡片按层级转成标题 + 列表 |
| FR-5 | 写入 Vault | 一键写入长图和笔记；另一条回答同名不覆盖（加序号）；同一条回答再收藏覆盖原文件夹，原文件夹已被整理走则只提示「已收藏过」不再写（2026-11-02 用户决定）；写入失败时退回浏览器下载，并说明原因。没选 Vault 文件夹（比如对方没装 Obsidian）时只把长图下载到浏览器下载目录，进度卡最后一步标「无 Obsidian」、写「无法保存，长图已下载」（2026-11-03 用户决定） |
| FR-6 | 提问与元数据 | 笔记带提问原文、来源链接、北京时间、标题 |
| FR-7 | 状态与失败 | 每步可见；任一步失败给原因，已生成的部分照样保存并标「不完整」，不假装成功 |
| FR-8 | ~~收藏时写一句~~ | 2026-11-10 用户决定删掉（基本没用过）：进度卡不再有「为什么存」输入框，笔记不再写 `why`。旧笔记里已写的不动，再收藏同一条时会被新笔记覆盖、不保留。编号保留不复用。原要求：存进 Vault 后进度卡底部出现「为什么存？写一句（可不填）」，回车只改笔记：frontmatter `why` + 正文最上面 `[!note] 为什么存` 框（2026-11-04 用户选 A 版） |
| FR-9 | 改版自检 | 收藏时笔记字数不到页面这条回答的一半（回答不到 20 字不比）、长图不到页面高度的一半：照样存，那一步标黄，顶部「已收藏，但可能不完整」，笔记加 `incomplete: true` 和 `[!warning]` 框；对话页上已有两个以上提问、却一条回答都没认出，并且页面静止 10 秒（不增删节点、文字不变）还这样，右下角提醒一次（每个对话一次）：「ChatGPT（Claude）改版了，收藏暂时用不了」+ 一个「复制修复请求」按钮，复制的是给 Claude 的修复请求（选择器命中数、对话区的 data- 属性名和次数、界面标记的取值，编号换成 ID、数字换成 N；不含对话文字、对话编号、账号信息），点了写「✓ 已复制。到 Claude Code 里 chatgpt-clipper 项目的会话粘贴发送。」；页面还在加载（提问还没出来）、还在变（流式输出、思考计时）、第一问还在生成（只有一个提问）不提醒，所以只有一问的对话改版了也不提醒；提醒之后认出回答或换了对话，提醒自动收起。插件安装、更新或重新加载后，后台给已开的 ChatGPT / Claude 页面补装新脚本，旧脚本收起自己的丝带和提醒，不用刷新就能收藏；补装不上的页面（休眠的标签页等）还连着旧插件，对话页一有变动就提醒「插件已更新，刷新这页才能收藏」+「刷新页面」按钮（每页一次）（2026-11-04 用户选 A 版：照样存、标黄提醒；2026-11-07 常浩反馈丝带挂上了还在提醒、页面没加载完就先弹；2026-11-11 常浩反馈提醒只说「可能改版了」不知道怎么办，看过三版预览选 C「查清了才提醒」，改成现在这样；2026-11-19 常浩选「只补装」（#12），同意加 `scripting` 和 chatgpt.com、claude.ai 两个站的 host 权限；从 11-19 之前的版本第一次升上来时，旧脚本不认让位，页面上可能有两条丝带，刷新一次即可） |
| FR-10 | 跳回原回答 | 笔记 `url` 带 `#clip-指纹前 10 位`，正文顶部「↩ 打开原回答」；打开后在对话里找这条回答（没渲染就往上翻，15 秒或翻到顶还没有就提示「没找到」），滚到回答开头，开头铺一抹淡黄、丝带同时变黄，约 2.5 秒淡掉（2026-11-04 用户先选闪黄光，嫌黄框太重后改选「开头一抹淡黄」） |
| FR-11 | 在 Obsidian 里打开 | 设置页填一次「收藏文件夹在 Obsidian 里的位置」（Vault 名/路径）；收藏完点进度卡绿块用 `obsidian://open` 打开这篇笔记，悬停时第二行换成「在 Obsidian 里打开 ↗」；没填时提示并打开设置页（2026-11-04 用户提出，选 A 版：整块能点、悬停提示） |
| FR-12 | 只收选中段落 | 在回答里选中文字，这条回答的丝带拉长成浅蓝斜纹（往右下斜）「荧光笔」，深蓝字竖着写「收藏选中·N块」（2026-11-04 先选 C 版上方标签，后改选「丝带统一」A 版：字都竖着写在丝带上；嫌深色斜纹上的白字看不清，再选「丝带清晰度」B 版：浅色斜纹配深色字，丝带加宽到 18px）；点丝带只收选中文字所在的整块（段落、标题、列表、表格、代码块；ChatGPT 的卡片网格整个算一块，Claude 的 Artifact 卡片算一块），长图和笔记都只有这几块。单独存成「日期 标题（节选）」文件夹，frontmatter `excerpt: true`，不覆盖整条收藏；同样几块再收覆盖这份节选，选了别的块另存。点丝带不清选区，取消选择后丝带恢复（2026-11-04 用户选 C 版选中样式） |

| FR-14 | 长图同时复制到剪贴板 | 点丝带收藏一整条回答（FR-1）或只收选中段落（FR-12）时，做好的长图同时放进系统剪贴板，可直接粘贴；进度卡「PNG 文件」一步写「NNNpx · 已复制」，没复制成写「未复制」，收藏照常完成。整段收藏（FR-13）不复制、不动剪贴板（2026-11-07 用户提出） |
| FR-15 | 一键导出 PDF 给 AI | 收藏完，进度卡底部（原「为什么存」的位置）有「📄 导出 PDF」按钮，旁边写「默认存储地址为「下载」」；点了不弹打印框，直接存进 Chrome「下载」根目录，文件名同收藏文件夹「日期 标题.pdf」（节选带「（节选）」、整段带「（整段）」），重名加序号。按钮变「正在导出 PDF…」，导好写「📄 已存到「下载」· N 页」+「在访达中显示」；没导出成写「没导出成：原因」+「重试」；导出中卡片不自动关。单条、节选、整段收藏都有，「已收藏过」和「无 Obsidian」时也有（快照做成了就能导）。PDF 内容：标题、「来源 · 北京时间」、原链接，提问，回答按页面上的样子排成 A4（版心比回答窄就整页缩小），文字可选中；图片、表格、代码块和有边框或底色、不到半页高的框（卡片、提示框）整块不跨页；整段每一轮一节（小标题是提问开头）。不附长图、不放 Obsidian 的属性区——长图发给 AI 会被缩到看不清，图文同页 AI 才能对照着看（2026-11-10 常浩确认）。做法：插件用 `debugger` 权限把自己的打印页打成 PDF，导出那一两秒浏览器顶部会出现「已开始调试此浏览器」提示条，点了提示条上的「取消」会打断导出（2026-11-10 常浩确认加权限、选 A 版入口） |

## 5. 技术方案（依据 [recon/2026-11-02-侦察记录.md](recon/2026-11-02-侦察记录.md)）

- **定位回答**：用稳定的数据属性 `[data-chatgpt-search-unit-key$=":assistant"]`，不依赖带哈希后缀的类名；选择器集中在一个适配模块里，ChatGPT 改版时只改这一处。
- **离线快照**（长图的来源）：复制回答节点，逐元素写入计算后样式，去掉类名和脚本；边框、颜色、填充、字号、行高、宽高必须写全（避开 Tailwind `0 solid` 的坑）；处理伪元素；图片转 base64。系统字体，不打包字体。
- **长图**（[原型①结论](recon/2026-11-02-原型1-长图.md)）：用离线快照经 SVG foreignObject 栅格化成 PNG；与浏览器真实渲染逐像素对比，布局完全重合，只有字形抗锯齿差异。CDP 撑高视口截图（需 `debugger` 权限）留作后备和回归基准；滚动拼接方案放弃。
- **Markdown**：针对 DIL 组件（Box / Grid / Text / Table / MarkdownRoot）写转换规则。
- **写入 Obsidian**：设置页用 File System Access API 选目标文件夹，保存目录句柄（IndexedDB），之后直接写；不依赖 Obsidian 插件或本地服务。
- **技术栈**：MV3 + TypeScript + WXT；测试用 Playwright 跑固定测试页，另加真实 ChatGPT 页面的手工验证。

## 6. 隐私与安全

- 只处理用户点选的那条回答，不扫描其他对话，不读账号资料。
- 全部本地处理：无服务器、无遥测、不上传。
- 不保存 cookie、token、localStorage；快照去掉脚本和事件属性。
- 不上架；需要 `debugger` 权限时，截图期间浏览器会出现“正在调试”的提示条，可以接受。
- `debugger` 权限只用于导出 PDF（FR-15，2026-11-10 常浩确认加）：只接到插件自己开的打印页上，导完马上断开、关掉打印页；不接 ChatGPT、Claude 或其他网页。

## 7. 验收矩阵（M1 必测）

纯文字、标题列表加粗链接、表格、代码块、公式、卡片布局（Box/Grid）、图片、深色模式、超长回答（≥4000px），以及用户参考图那种流程卡片。每类至少 1 条真实回答，记录 PNG、MD 和对比截图。

## 9. 默认取舍（用户未改即按此执行）

1. 笔记带提问原文，折叠放在顶部。
2. 存到 `00 待整理/ChatGPT收藏/`，图片跟随 Vault 的 git 管理，量大后再考虑排除。
3. 截图期间出现的“正在调试”提示条可以接受（原型①后主方案不再需要 `debugger`，只在后备方案里出现）。
