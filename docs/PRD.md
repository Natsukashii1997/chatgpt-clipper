# ChatGPT 回答收藏器 PRD v2

> 2026-11-02 定稿为开发基线，替代 GPT 起草的《ChatGPT 高保真可编辑导出器 PRD v1.0》（原文存于 [reference/gpt-prd-v1/](reference/gpt-prd-v1/)，只作参考）。
> 形态：Chrome 桌面版 MV3 插件，自用，不上架。只做电脑版。

## 1. 为什么做

ChatGPT 聊天模式的好回答常带卡片、分栏、图标、表格等版式。复制粘贴只剩文字，截图又不能搜索和引用，所以好答案存不下来。

**目标**：在 ChatGPT 网页上一键把某条回答原样存进 Obsidian，以后能看到原样、搜得到、能引用。

**v1 改了什么**：v1 把目标定成“高保真可编辑导出器”（编辑器、图层树、E0–E3 编辑分级、Figma、SSIM 评分）。用户的真实需求是收藏，编辑功能放到最后一期（M3），届时再参考 v1。

## 2. 存什么：每条回答三件套 + 一篇笔记

| 产物 | 用途 | 要求 |
|---|---|---|
| `answer.png` | 看原样 | 整条回答的长图，和页面所见一致；不含侧栏、输入框、操作按钮 |
| `answer.html` | 原件存档 | 单文件，断网能打开；文字可选中复制；样式、SVG、图片全部内嵌；不含脚本、cookie、token |
| 笔记 `.md` | 搜索、引用、双链 | frontmatter + 提问 + 嵌入长图 + 正文 Markdown + 原件链接 |

笔记模板：

```markdown
---
source: chatgpt
url: https://chatgpt.com/c/…
captured: 2026-11-02 16:30   # 北京时间
title: 整体业务逻辑
tags: [chatgpt收藏]
---
> [!question]- 提问
> （提问原文）

![[answer.png]]

（回答正文 Markdown）

原件：[answer.html](answer.html)
```

存放位置（默认，可在设置里改）：

```
<Vault>/00 待整理/ChatGPT收藏/2026-11-02 整体业务逻辑/
  整体业务逻辑.md
  answer.png
  answer.html
```

## 3. 怎么用

1. 打开 ChatGPT 对话，每条回答旁出现「收藏」按钮（或点插件图标进入选择模式）。
2. 点一下 → 显示进度（截图 / 存档 / 转文字 / 写入）→ 完成后提示保存位置，可点开。
3. 首次使用时在设置页选一次 Vault 里的目标文件夹，之后不再询问；浏览器收回授权时再提示一次。

## 4. 功能需求

| 编号 | 需求 | 验收 |
|---|---|---|
| FR-1 | 只收藏用户点选的那一条回答 | 5 条回答的对话里只得到选中那条，不含提问气泡、按钮、其他回答 |
| FR-2 | 长图 | 超过一屏（≥4000px）的回答完整截取，无重复行、无缺口、无悬浮控件；和页面截图目视一致 |
| FR-3 | 离线 HTML | 断网打开，卡片、边框、图标、表格与原页面一致；关键元素纵向位置偏差 ≤2px；没有向 chatgpt.com 发出的请求 |
| FR-4 | Markdown | 可见文字 100% 保留；标题、列表、表格、代码、公式源码、链接结构正确；卡片按层级转成标题 + 列表 |
| FR-5 | 写入 Vault | 一键写入三件套；同名不覆盖（加序号）；写入失败时退回浏览器下载，并说明原因 |
| FR-6 | 提问与元数据 | 笔记带提问原文、来源链接、北京时间、标题 |
| FR-7 | 状态与失败 | 每步可见；任一步失败给原因，已生成的部分照样保存并标「不完整」，不假装成功 |

## 5. 技术方案（依据 [recon/2026-11-02-侦察记录.md](recon/2026-11-02-侦察记录.md)）

- **定位回答**：用稳定的数据属性 `[data-chatgpt-search-unit-key$=":assistant"]`，不依赖带哈希后缀的类名；选择器集中在一个适配模块里，ChatGPT 改版时只改这一处。
- **离线 HTML**：复制回答节点，逐元素写入计算后样式，去掉类名和脚本；边框、颜色、填充、字号、行高、宽高必须写全（避开 Tailwind `0 solid` 的坑）；处理伪元素；图片转 base64。系统字体，不打包字体。
- **长图**（[原型①结论](recon/2026-11-02-原型1-长图.md)）：用离线快照经 SVG foreignObject 栅格化成 PNG，和 HTML 出自同一份快照；与浏览器真实渲染逐像素对比，布局完全重合，只有字形抗锯齿差异。CDP 撑高视口截图（需 `debugger` 权限）留作后备和回归基准；滚动拼接方案放弃。
- **Markdown**：针对 DIL 组件（Box / Grid / Text / Table / MarkdownRoot）写转换规则。
- **写入 Obsidian**：设置页用 File System Access API 选目标文件夹，保存目录句柄（IndexedDB），之后直接写；不依赖 Obsidian 插件或本地服务。
- **技术栈**：MV3 + TypeScript + WXT；测试用 Playwright 跑固定测试页，另加真实 ChatGPT 页面的手工验证。

## 6. 隐私与安全

- 只处理用户点选的那条回答，不扫描其他对话，不读账号资料。
- 全部本地处理：无服务器、无遥测、不上传。
- 不保存 cookie、token、localStorage；导出的 HTML 去掉脚本和事件属性。
- 自用、不上架；需要 `debugger` 权限时，截图期间浏览器会出现“正在调试”的提示条，可以接受。

## 7. 验收矩阵（M1 必测）

纯文字、标题列表加粗链接、表格、代码块、公式、卡片布局（Box/Grid）、图片、深色模式、超长回答（≥4000px），以及用户参考图那种流程卡片。每类至少 1 条真实回答，记录 PNG、HTML、MD 三件套和对比截图。

## 8. 分期

| 阶段 | 内容 | 门槛 |
|---|---|---|
| M0 侦察 | ✅ 2026-11-02 完成：卡片在主 DOM；HTML 快照可行 | — |
| M1 MVP | ① 长图三方案比较（✅ 2026-11-02 选定快照栅格化）→ ② 插件骨架 + 收藏按钮 → ③ 三件套生成（补图片内联、公式字体、伪元素）→ ④ 写入 Vault → ⑤ 验收矩阵 | 第 7 节全过，用户日常使用一周无阻断 |
| M2 增强 | 在 Obsidian 里直接渲染 HTML 原件（小插件）；整段对话收藏；自动标签；研究能否保存 DIL 原始描述 | 用户确认需要 |
| M3 编辑 | 基于 HTML 原件编辑再导出；参考 v1 的编辑器、Figma 部分 | 用户确认需要 |

## 9. 默认取舍（用户未改即按此执行）

1. 笔记带提问原文，折叠放在顶部。
2. 存到 `00 待整理/ChatGPT收藏/`，图片和 HTML 跟随 Vault 的 git 管理，量大后再考虑排除。
3. 截图期间出现的“正在调试”提示条可以接受（原型①后主方案不再需要 `debugger`，只在后备方案里出现）。
