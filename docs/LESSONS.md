## 怎么写

- 每轮交接时自问「本轮踩到新坑了吗」：有就在下面追加一条，并在 CURRENT.md 的交接里写「本轮新坑：L-xx」；没有就写「无」。
- 一条一个坑，编号只增不改。写现象、根因、正确做法、证据。证据写到能查的程度（提交号、文件与章节、证据目录）；查不到就写「未核实」，不编。
- 结论被推翻时改条目并注明日期，不删。

## 怎么升级

- 同类坑第 2 次出现：把正确做法写进 AGENTS.md 或 docs/OPERATIONS.md（一句话硬约束进 AGENTS.md，操作细节进 OPERATIONS.md），条目的「升级」改成写到了哪里。
- 能用机器判定的：写成测试或脚本（如 `scripts/check-rules.mjs`），条目注明。
- 换个项目也成立的（不依赖本项目的业务、页面、发布脚本）：提议提升到全局坑 `/Users/nat/Documents/ChatGPT/个人/work/agent-kit/LESSONS.md`，写成 G-xx；原条目保留，末尾加一行「提升：已提升为全局 G-xx（日期）」。只出提案，用户批准才写。
- 条目超过约 30 条时整理一次：已升级、且之后没再犯的，归档到 `docs/history/`。
- 「升级」一行每条都要有，开头写层级词〔结构〕〔机检〕〔体检〕〔文字〕〔提醒〕之一，再写状态（未升级 / 不升级 / 部分升级 / 已升级 / 关闭）、日期、编号和去处；还没升级的写「〔提醒〕未升级。」。坑本身已被代码消除、不再需要升级的写「〔层级〕关闭（日期，依据）：证据」，层级写现在靠什么守住（回归测试没接进必经检查的写〔提醒〕），原来的记录保留。层级的含义和怎么选，以全局 LESSONS「怎么升级」为准。`scripts/check-rules.mjs` 会查。

## L-01 计算样式内联后边框变成粗黑框（2026-11-02）

- 现象：把 ChatGPT 回答复制出来，只写入“与浏览器默认值不同”的计算样式，独立渲染后每个块都多了 3px 左右的黑色实线框，SVG 图标变成实心方块。
- 根因：Tailwind 预设给所有元素 `border: 0 solid`。比较时宽度 `0px` 与默认值相同被省略，只剩 `border-style: solid`，于是按默认宽度 medium 和默认颜色黑色画出边框；SVG 的 `fill`/`stroke` 同理被省略。
- 正确做法：`border-*`、`outline-*`、`fill`、`stroke`、`color`、`background-color`、字号、行高、宽高一律写全，不做默认值比较；其余属性可以比较后省略。
- 证据：[docs/recon/2026-11-02-侦察记录.md](recon/2026-11-02-侦察记录.md)「离线 HTML 快照实验」；对比截图在证据目录 `2026-11-02-recon/02-快照v1-边框坑.jpg`、`03-快照v2-修正后.jpg`。
- 升级：〔提醒〕关闭（2026-11-19，积压清单组 15）：核实坑已被代码消除：`src/lib/snapshot.ts` 第 6–7 行 `ALWAYS` 把 `border-*`、`outline-*`、`fill`、`stroke`、颜色、字号、行高、宽高一律写全，不再和默认值比较；没有专门报红的回归测试，靠这处写法守住。此前：〔提醒〕未升级。（2026-11-19 补层级：代码已改成这些属性一律写全（`src/lib/snapshot.ts` 的 `ALWAYS`），没有专门报红的回归测试）

## L-03 `fallback-turn-N:K` 编号会随页面加载整体平移（2026-11-02）

## L-07 SVG foreignObject 栅格化时外部图片和网页字体全部丢失（2026-11-02）

- 现象：长图里回答的图片是空白框（只剩说明文字），公式换成系统字体、`≠` 显示成方框，脚本画的 canvas 空白。
- 根因：SVG 当图片画（`img.src = data:image/svg+xml`）时浏览器不加载任何外部资源，`<img src="https://…">`、`@font-face` 的 url 都不生效；canvas 复制节点只复制标签不复制画面。另外 `images.openai.com` 不给 CORS 头，内容脚本 `fetch` 直接失败。
- 正确做法：栅格化前把图片、用到且已加载的 `@font-face` 换成 `data:` 地址，canvas 换成 `toDataURL()` 的图片；同源资源内容脚本直接取，跨域图片交给后台按 `host_permissions` 取（只列需要的域名，不用 `<all_urls>`）。测试里用不带 CORS 头的路由模拟跨域图片，Playwright 的 `context.route` 能拦到扩展后台的请求。
- 证据：`tests/snapshot.test.mjs`「长图里有跨域图片、网页字体、脚本画的 canvas」（改前 14.70% 报红，改后 0.87%）；证据目录 `2026-11-02-m1-5-acceptance/answer-T2-修后.png`、`answer-T4-修后.png`。

## L-12 两个一样大的误差会互相抵消，修掉一个，另一个才冒出来（2026-11-03）

- 现象：修 P15（长图里能滚动的区域不画滚动条）后，长图高度少 16px、长代码框下面的内容整体上移 16px；把改动退回已提交版本，同样的位置也少 16px，只是以前测试都通过。

## L-24 内容脚本的 `matches` 不算 host 权限：只加 `scripting` 补装不了脚本（2026-11-19）

- 现象：照驿窗的做法在 `runtime.onInstalled` 里给已开页面补装内容脚本，只加了 `scripting` 权限，重载插件后页面照旧提醒刷新。探针：后台 `tabs.query({ url: [chatgpt.com、claude.ai] })` 查到 0 个标签页，`tabs.query({})` 拿到的 `url` 全是 `undefined`，`scripting.executeScript` 报「Cannot access contents of the page. - 根因：Chrome 里内容脚本的 `matches` 只管声明式注入，不算 host 权限；按网址查标签页和 `executeScript` 都要 `host_permissions`（或 `tabs` + host 权限）。驿窗的 manifest 本来就有 `host_permissions: https://chatgpt.com/*`，所以没踩到。
- 正确做法：要在后台对某站的已开标签页补装脚本，`host_permissions` 里写上同样的站点（站点范围和内容脚本相同，不扩大）；动权限前先问常浩（本项目权限逐项经他同意）。改完用真重载的用例验证，不能只看 manifest。
- 证据：探针 `~/Library/Application Support/chatgpt-clipper/evidence/2026-11-19-fr9-reinject/`（`green-new-code.txt` 只加 scripting 时用例仍红，`green-with-host.txt` 加 host 权限后通过）；`wxt.config.ts` 注释。
- 升级：〔提醒〕未升级（2026-11-19）：测试「插件更新或重新加载后，已开的页面不用刷新…」去掉这两个 host 权限会报红，但本项目测试没接进必经检查；换个插件项目也成立，可提议并进全局 G-35 的正确做法。

## L-25 取 Vault 文件夹、查授权一直不回：入库无限转圈，设置页停在「未选择」（2026-11-20）

- 现象：#14 合并、插件和页面都刷新后，常浩在真实 Chrome 里收藏，快照、PNG、MD 都过了，进度卡停在「入库」一直转圈；后台控制台空白、没报错；设置页「收藏存到哪里」停在网页初始的「未选择」，下面的状态提示是空的，而同一个库里的「在 Obsidian 里打开」路径能读出来。

- 正确做法：凡是等浏览器或后台回话的步骤都要限时（同 PDF 导出的分步限时）：取文件夹 + 查授权限时 5 秒，到时写明「读不出授权，去设置页重新选一次文件夹」并退回下载；页面等后台回「入库」限时 60 秒，到时标「超时」、退回下载、给「重试」；设置页到时写明并突出「选择文件夹」。用户手上的临时解法：设置页重新选一次文件夹。
- 证据：`tests/snapshot.test.mjs`「取 Vault 文件夹、查授权一直不回…」（旧代码下报红：进度卡 30 秒没收尾）；`~/Library/Application Support/chatgpt-clipper/evidence/2026-11-20-vault-hang/`。
- 升级：〔提醒〕未升级（2026-11-20）：本项目测试没接进必经检查；「等外部回话必须限时」换个项目也成立，可与 L-13 一起并进全局 G-35。

## L-26 Chrome 升级重启后，存着的文件夹句柄上所有操作都不回；卡住的读还会堵住同库的写（2026-11-20）

- 现象：#15 合并、打包后常浩说「还是入不了库」。在他的真实 Chrome 里点收藏，进度卡停在「入库」70 秒不动，#15 加的 5 秒、60 秒限时都没触发；页面限时调成 4 秒也不触发。
- 根因（三层，前两层有实测）：
  1. 他的 Chrome 里跑的不是刚打的包：打包后没在扩展页刷新成功，#15 实际没生效。当时没有任何办法看出浏览器里是哪一版。
  2. 加载新版后自检实测（后台）：读写 IndexedDB、取出目录句柄都是几毫秒；`queryPermission({mode:'readwrite'})`、`queryPermission({mode:'read'})`、`getDirectoryHandle()` 全部 3 秒不回。也就是 L-25 说的「两步之一」是查授权，而且不只查授权，这个句柄上的任何操作都不回。时间线：Chrome 158.0.8127.37 在 11-19 05:23 装到磁盘，11-20 06:04 重启后才跑 158；最后一次成功收藏是 11-18。常浩移除并重装插件、重新选文件夹后，设置页和后台自检全通，真实收藏写进了 Vault。Chrome 内部为什么不回没查清（对主进程 `sample` 两次，没有卡在系统调用上的线程）；「升级重启后旧句柄失效」是按时间线的推断。
  3. 代码缺口（用例可复现，是否在常浩那里发生过没有证据）：`idb()` 只在事务结束时回话，#15 的限时只是不等了，没中止事务；读卡住的事务一直占着库，后面所有写都排在它后面，设置页 `saveDir()` 又要先读旧句柄，于是「重新选文件夹」这条出路也被卡死，而且没有提示。
- 正确做法：
  - 等浏览器回话的每一步都限时，到时要中止事务、关连接，不只是不等（`idb()`：读 5 秒、写 30 秒）。
  - 补救路径不能依赖坏掉的东西：`saveDir()` 读不出、比不了旧句柄时照样存新的。
  - 查授权不回时改成试读文件夹（`probeDir()`），读得通照常写；都不回才算卡住。
  - 代码里带打包时间，设置页显示，并提供自检（设置页「自检」按钮、页面 `clipper-diag` 事件）：先确认浏览器里跑的是哪一版，再看卡在哪一步。复现不出的问题先加自检取真实证据，不要按推断连改两轮。
  - 用户手上的解法：设置页重新选一次文件夹；不行就移除后重装（会清掉「已收藏」记录和设置，Vault 里的文件不受影响）。
- 证据：`tests/snapshot.test.mjs`「存着的文件夹读不出、读它的事务一直不结束…」（旧代码下报红：`'写被堵住' !== '写进了'`）、「取 Vault 文件夹、查授权一直不回…」（加了「只有查授权不回照常入库」）、「自检…」；`~/Library/Application Support/chatgpt-clipper/evidence/2026-11-20-vault-hang-2/`（`red-old-code.txt`、`full-*.txt`、两份 Chrome 采样）。
- 升级：〔提醒〕未升级（2026-11-20）：「未打包插件要能看出浏览器里跑的是哪一版」「限时要连带中止，不只是不等」换个项目也成立，可提议并进全局 G-35。

## L-27 ChatGPT 页面里藏着同一对话的副本：按选择器查全页会把副本也算进去（2026-11-23）

## L-28 ChatGPT 长对话也是虚拟列表、行没有序号，直接滚到顶会被拉回：按页面位置编号读整段会从中间开始（2026-11-23）
