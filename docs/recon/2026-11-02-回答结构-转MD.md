# 回答 DOM 结构侦察：转 Markdown 用（2026-11-02）

为 FR-4（Markdown 笔记）定转换规则。Claude 用 Claude in Chrome 在用户指定的一条对话里只读结构（标签、数据属性、层级、文字长度），没有读正文、没有点击、没有碰输入框。样本：5 条回答，4 条 DIL 卡片回答（高 2037–3879px），1 条「文档块」回答（9058px）。对话内容不入库。

## 结论

1. **DIL 组件有稳定的数据属性 `data-d-component`**，不用看 `Box-xxx` 这类带哈希后缀的类名。实测出现的值：

   | 值 | 标签 | 含义 |
   |---|---|---|
   | `title` | H1 / H2 | 标题（`data-d-size=xl/lg`） |
   | `text` | P / SPAN | 段落 / 行内文字；行内加粗看计算后的字重 |
   | `box` | DIV | 容器；`data-d-has-border` 的是带边框的卡片 |
   | `grid` / `grid-item` | DIV | 卡片网格；`grid-item` 是 `display: contents`，`checkVisibility()` 返回 false 但内容看得见 |
   | `row` | DIV | 横排（图标 + 文字、箭头） |
   | `divider` | DIV | 分隔线，无文字 |
   | `list` / `list-item` | OL / UL / LI | 列表；`data-d-marker=number/bullet`，编号放在空的 `SPAN[data-d-marker]` 里，内容在后面的 DIV |
   | `table` / `table-row` / `table-cell` | DIV / TR / TD·TH | 表格；**没有 thead**，表头是第一行的 TH；单元格里是 P |
   | `code` | CODE | 只见到行内代码（在 P 里，单行） |
   | `badge` | DIV | 标签胶囊，有文字 |
   | `pressable` | SPAN `role=link` | 文件引用，`aria-label="Open <文件名>"`，**没有 href**；后面紧跟一个隐藏的 `SPAN[data-markdown-copy="exclude"]`（「打开文件」） |
   | `icon` | svg | 图标，无文字 |

2. **文档块（writing block）自带 Markdown 原文**：`[data-client-defined-widget="writing_block"]` 里有一个元素带 `data-markdown-copy-text`，值就是这块的 Markdown 源码（样本 5631 字），比从渲染结果反推准确；直接用。块头 HEADER（「文档」字样）和两个按钮不属于正文。
3. ChatGPT 自己的复制标记：`data-markdown-copy="exclude"` 的元素不进复制结果，转 MD 时同样跳过。
4. 回答开头的读屏标题是 `H4[data-conversation-role="assistant"]`（`sr-only`），跳过。
5. **提问和回答在同一轮**：`[data-content-search-turn-key="fallback-turn-N"]` 里依次是 `fallback-turn-N:0:user` 和 `fallback-turn-N:K:assistant`。提问节点里只有一个 DIV 放文字，没有图片、没有读屏标题。取「回答前面最近的 `:user` 节点」，同轮、跨轮都适用（测试页是跨轮的）。
6. 本对话里**没有公式、没有代码块（pre）、没有链接（a[href]）**。这三种按普通 Markdown 渲染的通用结构写规则（KaTeX 的 `annotation[encoding="application/x-tex"]`、`pre > code.language-*`、`a[href]`），在测试页上覆盖，真实页面未核实。

## 转换规则（据此实现于 `src/lib/markdown.ts`）

- 跳过：插件自己的节点、读屏标题、`data-markdown-copy="exclude"`、svg、按钮、看不见的元素（`display: contents` 不算看不见；1×1 绝对定位的读屏文字算看不见）。
- 文档块：直接输出 `data-markdown-copy-text`。
- 卡片：`grid-item` 和带边框的 `box` 各转成一个列表项，第一块短文字加粗当小标题，其余转成下一级列表；卡片套卡片就逐层缩进。
- 表格：第一行当表头，单元格里多段用 `<br>` 连接，`|` 转义。
- 行内：字重 ≥ 600（且外层不是）→ `**…**`；`code` → 反引号；`a[href]` → `[文字](链接)`；文件引用只留文件名。

## 补充：代码块（2026-11-02，M1 验收 T1，测试对话，只读）

- 代码块整块是 `[data-client-defined-widget="code_block"]`，里面 `[data-code-block][data-markdown-copy="code-block"]`；块头是它的第一个子元素 `[data-markdown-copy="exclude"]`：图标 svg + 一个只有文字的 DIV（语言名，如「Python」「Bash」）+ 按钮（复制、换行、运行）。没有 `data-markdown-copy-text`。
- 可运行的（Python）用代码编辑器显示：`.cm-content[contenteditable][data-language="python"]`，下面一行一个 DIV，空行里只有 `<br>`，缩进是行首的空格文字。只读的（Bash）是 `pre > code`，code 没有 `language-*` 类，换行是 `<span>\n</span>`。
- 代码框有内部滚动（T1 为 431/504px），长图只截到看得见的部分（矩阵 P9）。
- 转换规则：认 `[data-markdown-copy="code-block"]`，有 `[data-language]` 就逐行取它的子 DIV，否则取 pre；语言取 `data-language`，没有就取块头文字转小写。实现于 `src/lib/markdown.ts` 的 `codeBlock`，选择器在 `src/lib/adapter.ts`。
- 未核实：代码很长时编辑器是否只渲染可见的一段（若是，笔记会缺行）。
