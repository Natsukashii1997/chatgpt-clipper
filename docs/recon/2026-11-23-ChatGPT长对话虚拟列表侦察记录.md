# ChatGPT 长对话虚拟列表侦察记录（2026-11-23，#32）

样本：常浩的 ChatGPT 对话「梳理数字分身框架」（5 轮，每条回答 1.5 万～2.5 万像素高；内容不入库）。Claude in Chrome 在常浩的真实 Chrome 里只读、只滚动，没发消息。

## 看到的

1. **每一轮包在 `[data-virtualized-turn]` 里**，style 只有 `contain: size; overflow-y: clip; height: Npx; margin-top: Npx`，没有序号。里面的 `[data-turn-key]`、`[data-content-search-turn-key]` 都是 36 字符的 UUID；问答各一条 `data-chatgpt-search-unit-key="<UUID>:0:user"`、`"<UUID>:2:assistant"`。页面上的先后就是对话顺序。
2. **虚拟列表**：只把视口附近的一两轮留在页面里，远处的从页面上删掉（不是藏起来），`scrollHeight` 随加载在 5.8 万～8.1 万之间变。打开对话时页面上是最近 3 轮；分步往上滚到顶，最早那一轮（打开时不在页面上）才出现。
3. **直接把滚动位置设到很远会被拉回**：`scrollTop = 0`（从 57764）设完 1.5 秒后还是 57764，`scrollTo({behavior:'instant'})` 一样；相对滚 3000 像素或每次两屏能生效，分 7 步滚到了顶。`scroll-behavior` 是 `auto`，页面可见、有焦点。
4. 页面里另有一块隐藏的页面层（祖先 `display:none`）放着同一对话或刚看过的对话的副本（见 L-27、#30）。

## 对实现的影响

- 不能再用「在页面上的位置」当顺序号认下一条：滚动中前面插入、删掉行，位置就变了（#32 的根因：从第 4 问开始导，不报错）。
- 改成按每一条自己的标识（`data-chatgpt-search-unit-key`）记读过没有，下一条取页面上紧跟在刚读那条后面的；「读到哪一条为止」也按标识认。
- 回到顶部、读完滚回原位都分步走，每步最多两屏，到顶后停稳几次再开始读。
- 没试：几十轮以上的对话；网速慢时往上加载要多久；生成中的回答。

## 第二轮（#33 合并后，2026-11-23 14:05–14:35）

#33 按「分步滚、不发滚轮事件」改完，真实页面上仍只读到 1 条。再测：

1. **「贴住最新消息」**：程序改滚动位置（不发滚轮事件），每步往上两屏，滚到刚好露出上一轮（d7b9）时页面自己跳回底部（41416 → 56676），反复 80 多次都这样，永远退不过一轮。第一次侦察能滚到顶，是因为正好在用真实滚轮滚过之后。
2. **先发滚轮事件再滚**：每步先在滚动容器上发 `new WheelEvent('wheel', { deltaY: 负数 })`（脚本发的，不是真实输入），再把 `scrollTop` 减两屏：37 步、17 秒滚到顶，最早一轮 a158 出现，`scrollHeight` 涨到 82237。
3. **往下逐条读**：从顶上按标识找「刚读那条后面没读过的」，每次滚动前同样发滚轮事件：5 轮 10 条按顺序全读到（a158 问答、e1a7 问答……5ff7 问答），没有丢。慢在半屏半屏地走过两万像素的长回答，改成没有下一条时直接跳到刚读那条末尾附近。
4. 刚打开页面的几秒里，有时会先出现一份 5 轮都在、整页只有 1900 像素高的渲染，8～12 秒后才稳定成只留最后 3 轮的虚拟列表。用户拉丝带时页面早已稳定，没处理这种情况。
