# 整段收藏侦察记录（2026-11-04，FR-13 开工前）

方式：Claude in Chrome 新开标签页，只读脚本读结构；只改过滚动位置，读完滚回原位（4673 → 4673），关标签页；未点击、未碰输入框。

## Claude 网页版

样本：常浩建的测试对话 `https://claude.ai/chat/1a834298-9100-4af0-9f87-83d4237a84f0`（6 问 6 答，不私密）。

1. **对话是虚拟列表**：`[data-testid="transcript-sizer"]` 下依次是 `transcript-leading`（占位）、`transcript-spacer`（占位）、若干 `[data-testid="transcript-row"]`、尾部 `transcript-spacer`。每行带 `data-index`（0 起，问和答各占一行，按顺序交替）。打开时停在底部，只渲染第 5–11 行；第 0–4 行不在页面里。
2. **总高度一开始就定了**：滚动容器（回答最近的可滚动祖先，`overflow-y-auto`）`scrollHeight` 始终 5431，不随滚动变化；没渲染的行由占位块撑着。说明整段对话的数据已在页面里，不用往上翻触发加载（很长的对话会不会分页加载，这次样本太短，没验证）。
3. **滚到哪渲染哪**：滚到顶部后 150ms 内第 0–3 行就渲染出来；按一屏一屏往下滚，每步等 500ms，各行依次出现，离得远的行会被卸掉（滚到底只剩 5–11）。行渲染出来时高度就是最终高度。
4. **没有 `content-visibility`**：页面上没有元素的 `content-visibility` 不是 `visible`。行只要在页面里，即使在屏幕外，计算样式也是全的，现有快照（复制计算样式）能截。
5. 插件的丝带只挂在已渲染的回答上（当时 4 条回答渲染了，4 条丝带）。

**对实现的影响**：逐条读时按 `data-index` 走，每条先滚到它附近、等这一行出现（轮询，最多等几秒），趁它还在页面里立刻截长图、转 Markdown、配上前一行的提问，再去下一条；不能先滚一遍再统一截（前面的行会被卸掉）。读完滚回原位。

## ChatGPT

样本：常浩给的对话 `https://chatgpt.com/c/6ae9a69a-b53c-83ee-b7ef-24ecc3a05c6d`（3 问 3 答，不私密；内容不入库）。只改过滚动位置，读完滚回原位（2317 → 2317），关标签页。

1. **3 轮全在页面里**：每轮 `[data-content-search-turn-key="fallback-turn-N"]`（N 从 0 起）里同时有 `:user` 和 `:assistant` 两条消息；滚到顶、中间、底部，3 轮一直都在，高度和字数不变，`scrollHeight` 始终 3074。这个样本看不出 ChatGPT 会不会卸掉远处的行（太短）。
2. **对话里没有 `content-visibility`**：页面上 4 个 `content-visibility:auto` 的元素都在左侧边栏 `nav` 里（对话历史，每个 36px），不在对话和回答里。
3. 滚动容器是 `.thread-scroll-container`（回答最近的可滚动祖先），和 M1 侦察一致。

**对实现的影响**：和 Claude 用同一套逐条读的办法（滚到附近、等这一条出现、立刻截），对两边都成立；ChatGPT 长对话若也卸载行，这套办法同样能应付。

## 消息大小

浏览器扩展消息上限约 64 MiB（JSON 序列化后）。长图以 data: URL 传给后台，一张长回答的 PNG 可能几 MB，十几条回答一起传有超限风险。做法：整段收藏分批写入，每条回答的长图单独发一条消息，最后再写笔记；不用测极限。
