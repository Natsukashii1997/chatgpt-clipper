# 第 0 步侦察记录（2026-11-02）

样本：用户指定的一条私人对话里一条带卡片布局的回答（约 2900 字、4144px 高；对话内容不入库）。
方式：Claude in Chrome 新开标签页，只读页面结构；本地临时插入一个快照浮层做渲染实验，结束后已移除并关闭标签页。

## 结论

1. **卡片回答渲染在主页面 DOM 里**，不在 iframe、不用 Shadow DOM、没有 canvas。内容脚本可以直接读取。
2. 回答由 ChatGPT 的 **DIL 渲染器**生成（类名 `DilResponseRoot-*`、`DilRenderer-*`、`Box-*`、`Grid-*`、`Text-*`、`Table-*`、`MarkdownRoot-*`）；页面另有一个 0×0 的隐藏 iframe `cdn.platform.openai.com/deployments/dil/v15/runner…`，推测负责运行 DIL，但渲染结果落在主 DOM。
3. **类名带哈希后缀，会随版本变化**：定位要用稳定属性，不靠类名。
   - 每轮：`[data-content-search-turn-key="fallback-turn-N"]`
   - 每条消息：`[data-chatgpt-search-unit-key="fallback-turn-N:K:user|assistant"]`
   - 旧的 `[data-message-author-role]` 已不存在。
4. 样式靠 CSS 变量和 chatgpt.com 同源样式表（21 个外链 + 4 个内联），字体是系统字体栈（`-apple-system` 等），**无需打包字体**。
5. 图标是 20 个内联 SVG（无 `<use>` 引用精灵图），可原样保留；本条无图片、无公式、无代码块，有 2 个表格。
6. 回答高 4144px，视口 749px；滚动发生在内部容器 `.thread-scroll-container`，不是文档本身。**长图不能直接用 `captureBeyondViewport`**，要么临时撑开该容器、要么滚动分段拼接，需在插件原型里验证。

## 离线 HTML 快照实验

做法：复制回答节点 → 每个元素写入计算后样式（与浏览器默认值不同的项）→ 去掉类名 → 放进 `srcdoc` iframe 渲染。

| 版本 | 结果 |
|---|---|
| v1 | 边框变粗黑框、图标变方块。原因：Tailwind 预设 `border: 0 solid`，和默认值比较时宽度 0 被当作“未变”漏写，只剩 `border-style: solid` → 默认 3px 黑框 |
| v2 | 边框、颜色、填充、字号、行高、宽高一律写入 → 视觉与原页面基本一致；9 个标题/表格的纵向位置与原页面**逐像素一致**（差 0px），表格宽度一致 |

- 361 个节点，耗时约 0.24 秒，HTML 约 0.98MB（未压缩、未去重，可优化）。
- 遗留：快照文档总高度 9382px，大于原回答 4176px，内容位置一致，推测是某个定位元素撑高了底部空白，原型里需裁掉；7 个伪元素有 content，待处理。

## 对方案的影响

- HTML 存档这条路**成立**，难度低于预期；用“计算样式内联”即可，不需要 PRD v1 那套规范节点模型。
- Markdown 转换要针对 DIL 结构（Box/Grid/Text）写规则，不能假设是普通 Markdown 渲染。
- 长图截取是剩下的主要技术风险，放进 M1 第一个原型验证。
- 中期可研究：DIL 原始描述是否在对话数据里，若有，可作为最原始的“源件”一并保存（需评估是否依赖未公开接口）。
