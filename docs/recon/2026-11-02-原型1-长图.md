## 各方案的利弊

- **A**：浏览器的真实渲染，最可信。代价有三：要 `debugger` 权限，截图时有“正在调试”提示条；要临时改视口大小，页面会闪一下重排；页面上其他悬浮物也会被截进去（测试图里就截进了 Claude in Chrome 的橙色光标）。
- **B**：Chrome 实测要求“扩展被调用过”才给截屏（即使声明了 `<all_urls>`，根因未核实，见 LESSONS L-02）；正式版用户点插件图标就能满足。但每屏至少约 0.5 秒（每秒最多 2 次），9000px 要拼约 15 段，还有滚动动画和吸顶元素的拼接风险。C 已经可用，B 没必要再投入。
- **C**：最快，不需要额外权限，不碰页面，不会截进悬浮物。PNG 和离线 HTML 出自**同一份快照**，三件套天然一致。

## 决定

- 长图用 **C**。A 留作后备（快照失败时退回，或开发期用来做视觉回归基准）。B 放弃。
- C 的已知限制，M1 要补：
  1. 跨域图片必须先转 base64，foreignObject 里不能加载外部资源（本次样本没有图片，未验证）。
  2. 公式（KaTeX）用网络字体，要把 `@font-face` 内嵌（未验证）。
  3. 伪元素内容尚未写入快照（侦察时发现 7 个）。
  4. 深色模式、代码块、表格横向滚动未覆盖。
  5. DPR 2（Retina 屏）未测；本机这次是 DPR 1 的外接屏。
