# ChatGPT「还在生成」标记侦察记录（2026-11-23，#35）

样本：常浩的 ChatGPT 对话「Chrome扩展开发流程」（即 15:28 经常浩同意发的测试对话，1 问 1 答，已答完；内容不入库）。Claude in Chrome 在常浩的真实 Chrome 里新开一个标签页，只读页面结构、只读 ChatGPT 自己加载的前端脚本文字，没发消息、没点停止。

## 看到的

1. **页面结构**（答完的那一轮）：回答 `[data-chatgpt-search-unit-key$=":assistant"]` 往上第 2 层是 `div[data-talvt-turn-state="complete"]`，提问也在同一个元素里（每一轮的问答共用一个）；再往上是 `[data-content-search-turn-key]`、`[data-turn-key]`、`[data-virtualized-turn]`。页面上没有 `[data-testid="stop-button"]`，也没有 `aria-label="停止"` 的按钮（没在生成）。
2. **前端脚本里这个属性的来历**：渲染每一轮的组件写着 `"data-talvt-turn-state": <这一轮>.status`。同一个组件里拿这个 status 比的值只有三个：
   - `"in_progress"`：用来判断「这是正在回答的一轮」（`isActiveResponseTurn` 旁边、`"in_progress"===status`），生成中不显示「用时」；
   - `"cancelled"`：显示「You stopped（after …）」，即用户点了停止；
   - `"complete"`：答完。
3. 15:29 那次真实页面实测（见 #35）：生成中输入框旁的停止键是 `<button type=button aria-label="停止">`，没有 `data-testid`；思考阶段（还没出正文）页面上没有回答元素，丝带挂不上。

## 对实现的影响

- `chatgptSite.streaming` 改成看回答外面的 `data-talvt-turn-state` 是不是 `in_progress`：是数据属性，不随界面语言变，符合 AGENTS「只用稳定的数据属性」；而且直接落在这一条回答所在的轮上，不再靠「页面上有停止键、而且是最后一条」去推。
- `cancelled`（用户停掉的）不算还在生成：回答已经定了，照常导进去。
- 思考阶段没有回答元素、没有丝带，拉不了，不用处理。

## 没验到的

- 生成中 `in_progress` 这个值是从脚本里读出来的，没在真实页面上亲眼看到属性变成 `in_progress`：要看得发一条提问触发生成，按约定要常浩先同意。合并后在真实 Chrome 走 S9「生成中那次」时一并确认。
- 页面在别的界面（如项目里的对话、临时对话、Work 模式）是否同样有这一层，没试。
