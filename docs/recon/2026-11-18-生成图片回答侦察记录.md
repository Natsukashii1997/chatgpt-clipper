# 生成图片的回答侦察记录（2026-11-18）

来由：常浩 2026-11-18 21:42 复制的修复请求：chatgpt.com 对话页上回答选择器 `[data-chatgpt-search-unit-key$=":assistant"]` 命中 0 个、提问 2 个，界面标记里有 `generated-image-gallery`。
方式：Claude in Chrome 在常浩的 Chrome 里新开标签页，只读页面结构（标签名、data- 属性、尺寸、图片地址的协议和域名），编号换成 ID；没有读对话文字，没有点任何按钮。看了 4 个对话：1 个生成图片对话（两问两答）、3 个普通对话（1、2、5 轮）。

## 结论

1. **不是全站改版**。普通对话的回答标记照旧：`div[data-chatgpt-search-unit-key="fallback-turn-N:2:assistant"][data-content-search-unit-key][data-chatgpt-search-message-ids="ID ID"]`，3 个普通对话都认得出。
2. **生成图片的回答换了一种结构**，没有 `…:assistant` 标记，也没有 `data-content-search-unit-key`：

```
div[data-turn-key] > div[data-content-search-turn-key] > div > div[data-talvt-turn-state="complete"] > div[data-spacing="activity"]
  div                                   ← 提问
    h4[data-conversation-role="user"]（读屏标题）
    div[data-chatgpt-search-unit-key="ID:0:user"][data-chatgpt-search-message-ids="ID"]   ← 提问照旧有标记
  div
    span[data-chatgpt-agent-turn-start]
    button[data-turn-disclosure-button]（「已处理 1m」那行，在回答外面）
  div                                   ← 回答
    h4[data-conversation-role="assistant"]（读屏标题「ChatGPT 说：」）
    div[data-response-body="ID"][data-chatgpt-search-message-ids="ID"]   ← 整条回答（768px 宽，和普通回答同一栏）
      div > div[data-testid="generated-image-gallery"] > div > div[data-web-image-tile="true"]
        button[data-testid="generated-image-preview"][aria-label="已生成图像 1"] > img[alt="已生成图像 1"]
        div（opacity 0 的遮罩）
        div（底部按钮条）> button「编辑」[aria-label="编辑生成的图像 1"]、button[aria-label="分享生成的图像 1"]
```

3. **怎么和普通回答区分**：普通回答里也有 `data-response-body`，但它在 `…:assistant` 那个元素里面、不带 `data-chatgpt-search-message-ids`；生成图片的 `data-response-body` 自己带消息编号（两者编号相同）。所以选择器用「带消息编号的 `data-response-body`，且不在 `…:assistant` 元素里面」，3 个普通对话里新旧选择器命中完全相同（5/5、2/2、1/1），生成图片对话 2/2，没有一条被重复认出。
4. **图片是 `blob:https://chatgpt.com/…` 地址**（1254×1254、1983×793），和页面同源。长图里内嵌图片走同源那条路（内容脚本直接 `fetch` 这个 blob 地址），不用加 `host_permissions`；测试页照样用页面脚本生成 blob 地址，长图逐像素比通过。真实 Chrome 里内容脚本能不能读页面建的 blob 地址，要常浩刷新插件后实测一次。
5. **图上的「编辑」「分享」按钮**：鼠标悬停时叠在图片底部，属于界面，长图、笔记、指纹都不要（放进 ChatGPT 的 `NOISE`）。预览按钮里包着图片本身，要留；转 Markdown 本来整个跳过按钮，所以给预览按钮开了例外（`MD.keepButton`），笔记里写图片说明「已生成图像 1」（blob 地址离开页面就失效，不写成图片链接）。
6. 修复请求里另有一个 `data-talvt-turn-state="in_progress"`，这次看的对话两轮都是 `complete`，推断常浩复制时某一张图还在生成或刚生成完，未核实。

## 改了什么

`src/lib/adapter.ts`：`ANSWER_SELECTOR`（ChatGPT 加上生成图片的回答）、`NOISE`（ChatGPT 加图上按钮）、`answerKey`（没有单元标记时用消息编号）、`MD.keepButton`；`src/lib/markdown.ts`：按钮例外。测试页 `tests/fixtures/image-answer.html`，用例 `tests/snapshot.test.mjs`「ChatGPT 生成图片的回答」。
